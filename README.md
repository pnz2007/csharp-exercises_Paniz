## تمرین اول: آشنایی با Git و GitHub

### سؤال اول: Git چیه و به چه دردی می‌خوره؟

ابزار Git یه نرم‌افزار برای کنترل نسخه (Version Control) هست. یعنی هر تغییری که توی فایل‌های پروژه‌مون می‌دیم رو ثبت می‌کنه؛ یه جورایی مثل دفترچه‌ی خاطرات کد.

چندتا از کاربردهاش:

- هر وقت خواستیم می‌تونیم برگردیم به یه نسخه‌ی قبلی از کارمون.
- معلومه کی، چه تغییری و کجای پروژه داده.
- چند نفر می‌تونن هم‌زمان روی یه پروژه کار کنن بدون این‌که کار همدیگه رو خراب کنن.
- هر بار یه مرحله از کار تموم می‌شه، یه Commit می‌زنیم؛ یعنی از وضعیت فعلی پروژه یه عکس می‌گیریم و ذخیره‌ش می‌کنیم.

### سؤال دوم: GitHub چیه و چه فرقی با Git داره؟

سایت GitHub یه سرویس آنلاینه که پروژه‌هایی که با Git مدیریت می‌شن رو روی اینترنت نگه می‌داره. این‌جوری کدمون فقط روی لپ‌تاپ خودمون نیست؛ از هر جایی بهش دسترسی داریم، می‌تونیم با بقیه به اشتراک بذاریم و با هم روش کار کنیم.

فرقشون به زبون ساده:

- ابزار Git یه نرم‌افزاره که روی کامپیوتر خودمون نصب می‌شه و بدون اینترنت هم کار می‌کنه.
- سایت GitHub یه وب‌سایته که نسخه‌ی آنلاین پروژه‌مون اون‌جا ذخیره می‌شه.
- ابزار Git رایگان و متن‌بازه و مال شرکت خاصی نیست؛ ولی سایت GitHub مال مایکروسافته.
- سایت‌های دیگه‌ای مثل GitLab و Bitbucket هم همین کار GitHub رو می‌کنن.

یه مثال: ابزار Git مثل دوربینیه که از هر مرحله‌ی کار عکس می‌گیره، و سایت GitHub مثل یه آلبوم آنلاین که عکس‌ها رو اون‌جا می‌ذاریم تا بقیه هم ببینن.

## تمرین دوم: کلاس، صفت و رفتار

پرانتز جلوی اسم رفتارها یعنی اون یه متده. کد هر کلاس توی پوشه‌ی Tamrin02 و توی یه فایل جدا قرار داره و توی فایل Program.cs از هر کدوم یه نمونه ساختیم.

## تمرین سوم: HTTP و HTTPS

### سؤال اول: HTTP چیه؟

اسم کاملش HyperText Transfer Protocol هست. یه پروتکله؛ یعنی یه مجموعه قانون که مشخص می‌کنه مرورگر و سرور چطوری با هم حرف بزنن، درخواست بفرستن و جواب بگیرن.

مشکلش اینه که اطلاعات رو بدون رمز و به‌صورت متن ساده جابه‌جا می‌کنه. یعنی اگه کسی وسط راه (مثلاً روی Wi-Fi یه کافه) اطلاعات رو بگیره، راحت می‌تونه بخونه.

### سؤال دوم: HTTPS چیه؟

همون HTTP هست به‌اضافه‌ی حرف S که یعنی Secure (امن). توی HTTPS اطلاعات قبل از فرستاده شدن رمزنگاری (Encrypt) می‌شن.

این رمزنگاری با چیزی به اسم TLS انجام می‌شه که قبلاً بهش SSL می‌گفتن. پس حتی اگه کسی وسط راه اطلاعات رو بگیره، فقط یه مشت حروف درهم و بی‌معنی می‌بینه.

### سؤال سوم: فرقشون چیه؟

- از نظر امنیت: توی HTTP اطلاعات بدون رمز می‌رن، ولی توی HTTPS رمزنگاری می‌شن.
- از نظر آدرس: آدرس سایت با http یا https شروع می‌شه.
- از نظر پورت: معمولاً HTTP از پورت ۸۰ و HTTPS از پورت ۴۴۳ استفاده می‌کنه.
- از نظر گواهی: برای HTTPS سایت باید یه گواهی امنیتی (SSL Certificate) داشته باشه.
- از نظر ظاهر: کنار آدرس سایت‌های HTTPS یه علامت قفل می‌بینیم، ولی برای HTTP مرورگر عبارت Not secure رو نشون می‌ده.

### سؤال چهارم: چرا امروزه بیشتر سایت‌ها از HTTPS استفاده می‌کنن؟

- چون از اطلاعات مهم مثل رمز عبور، شماره کارت و اطلاعات شخصی محافظت می‌کنه.
- چون مرورگرها سایت‌های HTTP رو با پیغام Not secure نشون می‌دن و کاربر بهشون اعتماد نمی‌کنه.
- چون Google به سایت‌های HTTPS توی نتایج جستجو امتیاز بیشتری می‌ده.
- چون خیلی از امکانات جدید مرورگر (مثل دسترسی به دوربین و موقعیت مکانی) فقط روی HTTPS کار می‌کنن.
- چون گرفتن گواهی امنیتی الان رایگان شده؛ مثلاً با سرویس Let's Encrypt.

## تمرین چهارم: URL

### سؤال اول: URL چیه؟

اسم کاملش Uniform Resource Locator هست. به زبون ساده، آدرس کامل یه چیز روی اینترنته؛ حالا اون چیز می‌تونه یه صفحه، یه عکس، یه ویدیو یا هر فایل دیگه‌ای باشه. همون چیزیه که بالای مرورگر توی نوار آدرس می‌بینیم.

### سؤال دوم: بررسی قسمت‌های یه URL

این URL رو در نظر می‌گیریم:

</div>

```text
https://talabash.com/jewelry/women-gold-necklaces/
```

<div dir="rtl">

توضیح هر قسمت:

- پروتکل (Scheme) که این‌جا https هست و مشخص می‌کنه با چه قانونی به سایت وصل بشیم. چون https هست، ارتباط با سایت امن و رمزنگاری‌شده‌ست.
- زیردامنه (Subdomain) توی این آدرس وجود نداره؛ یعنی مستقیم وارد سایت اصلی می‌شیم. اگه آدرس با www شروع می‌شد، اون www زیردامنه بود.
- اسم دامنه (Domain Name) که این‌جا talabash هست و اسم اصلی سایته.
- پسوند دامنه (TLD) که این‌جا com هست. پسوندهای دیگه‌ای مثل ir و org و de هم داریم.
- پورت (Port) توی آدرس نوشته نشده، چون مرورگر خودش می‌دونه برای https باید از پورت پیش‌فرض ۴۴۳ استفاده کنه.
- مسیر (Path) که این‌جا jewelry/women-gold-necklaces هست و نشون می‌ده دقیقاً کدوم صفحه از سایت رو می‌خوایم. بخش اول یعنی دسته‌ی «جواهرات» و بخش دوم یعنی زیردسته‌ی «گردنبند طلای زنانه». علامت / آخر آدرس هم معمولاً یعنی این آدرس به یه دسته اشاره می‌کنه، نه یه فایل مشخص.
- پارامترها (Query String) توی این آدرس وجود ندارن، چون علامت سؤال توی آدرس نیست. اگه مثلاً محصولات رو فیلتر یا مرتب کنیم، ممکنه سایت چندتا پارامتر بعد از علامت سؤال به آدرس اضافه کنه.
- قطعه (Fragment) هم توی این آدرس نیست، چون علامت # نداره.

## تمرین پنجم: GET و POST

### سؤال اول: GET چیه؟

روش GET یعنی «یه چیزی بهم بده». وقتی می‌خوایم اطلاعاتی رو از سرور بگیریم و فقط ببینیم، از GET استفاده می‌کنیم. اطلاعات اضافه (مثل کلمه‌ای که جستجو کردیم) توی خود URL فرستاده می‌شه.

### سؤال دوم: POST چیه؟

روش POST یعنی «اینو بگیر و ذخیره کن». وقتی می‌خوایم اطلاعاتی رو برای سرور بفرستیم (مثل ثبت‌نام، ورود به حساب یا ارسال فرم)، از POST استفاده می‌کنیم. اطلاعات توی بدنه‌ی درخواست (Body) فرستاده می‌شه و توی URL دیده نمی‌شه.

### سؤال سوم: فرقشون چیه؟

- کار اصلی: روش GET برای گرفتن اطلاعاته و روش POST برای فرستادن اطلاعات.
- جای اطلاعات: توی GET اطلاعات داخل URL هست و همه می‌بیننش؛ توی POST داخل بدنه‌ی درخواسته.
- امنیت: برای رمز عبور هیچ‌وقت نباید از GET استفاده کرد، چون توی URL و تاریخچه‌ی مرورگر می‌مونه.
- حجم: طول URL محدودیت داره، پس GET برای اطلاعات زیاد مناسب نیست؛ ولی با POST می‌شه اطلاعات زیاد و حتی فایل فرستاد.
- ذخیره کردن: صفحه‌ای که با GET باز شده رو می‌شه توی Bookmark ذخیره کرد یا لینکش رو برای کسی فرستاد، ولی نتیجه‌ی POST رو نه.
- تکرار: اگه یه درخواست GET رو چند بار بفرستیم چیزی روی سرور عوض نمی‌شه، ولی تکرار POST ممکنه مثلاً یه سفارش رو دو بار ثبت کنه.

### سؤال چهارم: معمولاً کجا از GET استفاده می‌کنیم؟

- برای جستجو توی سایت‌ها.
- برای باز کردن یه صفحه یا دیدن یه محصول.
- برای دیدن لیست پست‌ها، فیلم‌ها یا محصولات.
- برای فیلتر کردن نتایج؛ مثلاً بر اساس قیمت یا رنگ.

### سؤال پنجم: معمولاً کجا از POST استفاده می‌کنیم؟

- برای ثبت‌نام و ورود به حساب کاربری.
- برای ارسال فرم «تماس با ما».
- برای گذاشتن نظر یا پست جدید.
- برای فرستادن عکس یا فایل.
- برای ثبت سفارش و پرداخت.

### مثال واقعی برای GET

جستجو توی Google: وقتی کلمه‌ی csharp رو جستجو می‌کنیم، این آدرس باز می‌شه و کلمه‌ی ما توی خود URL دیده می‌شه:

</div>

```text
GET https://www.google.com/search?q=csharp
```

<div dir="rtl">

یه مثال از یه API واقعی: با این درخواست، اطلاعات عمومی یه کاربر GitHub رو می‌گیریم و جوابش به‌صورت JSON برمی‌گرده:

</div>

```text
GET https://api.github.com/users/octocat
```

<div dir="rtl">

### مثال واقعی برای POST

ورود به حساب توی Instagram: وقتی نام کاربری و رمزمون رو می‌نویسیم و دکمه‌ی ورود رو می‌زنیم، اطلاعات با POST فرستاده می‌شه. برای همینه که رمزمون توی نوار آدرس دیده نمی‌شه.

## تمرین ششم: JSON و XML

### سؤال اول: JSON چیه؟

اسم کاملش JavaScript Object Notation هست. یه روش ساده و سبک برای نوشتن و جابه‌جا کردن اطلاعاته. اطلاعات به‌صورت جفت‌های «اسم و مقدار» (Key و Value) نوشته می‌شن و داخل آکولاد قرار می‌گیرن.

با این‌که اسمش JavaScript داره، تقریباً همه‌ی زبان‌های برنامه‌نویسی، از جمله C#‎، باهاش کار می‌کنن.

### سؤال دوم: XML چیه؟

اسم کاملش eXtensible Markup Language هست. اطلاعات رو با برچسب (Tag) می‌نویسه، خیلی شبیه HTML؛ با این فرق که اسم برچسب‌ها رو خودمون انتخاب می‌کنیم. هر اطلاعاتی بین یه برچسب باز و یه برچسب بسته قرار می‌گیره.

### سؤال سوم: چه کاربردی دارن؟

هر دو برای ذخیره کردن و جابه‌جا کردن اطلاعات بین برنامه‌ها هستن؛ مثلاً وقتی Client و Server با هم حرف می‌زنن یا وقتی یه API جواب می‌ده.

- فرمت JSON الان پرکاربردترینه: توی بیشتر APIها، اپ‌های موبایل، وب‌سایت‌ها و فایل‌های تنظیمات (مثل appsettings.json توی پروژه‌های C#‎).
- فرمت XML بیشتر توی سیستم‌های قدیمی‌تر و بزرگ، سرویس‌های SOAP، فایل‌های RSS و فایل‌های تنظیمات استفاده می‌شه.

### سؤال چهارم: چه فرق‌هایی با هم دارن؟

- ظاهر: فرمت JSON با آکولاد و جفت «اسم و مقدار» نوشته می‌شه، ولی XML با برچسب‌های باز و بسته.
- حجم: فرمت JSON کوتاه‌تر و سبک‌تره، چون توی XML اسم هر برچسب دو بار تکرار می‌شه (یه بار باز، یه بار بسته).
- خوانایی: خوندن JSON برای آدم‌ها معمولاً راحت‌تره.
- نوع داده: فرمت JSON عدد، متن، true و false و لیست رو مستقیم می‌شناسه؛ ولی توی XML همه‌چی متنه.
- امکانات اضافه: فرمت XML می‌تونه ویژگی (Attribute) و توضیح (Comment) داشته باشه، ولی JSON توضیح نداره.
- سرعت: پردازش JSON معمولاً سریع‌تره و توی JavaScript خیلی راحت خونده می‌شه.
